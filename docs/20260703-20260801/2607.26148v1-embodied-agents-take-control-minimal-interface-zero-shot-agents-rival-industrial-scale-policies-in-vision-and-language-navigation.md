## 摘要
自主具身智能体必须维持一个长时决策循环，涉及感知、行动、验证和自校正等众多步骤。当前系统通过任务专用工作流或具身策略维持这一循环。我们研究了第三种形式，即智能体具身控制，其中通用智能体自身持有该循环。以零样本导航作为受控测试平台，我们仅使用单目RGB相机和离散动作，评估了三种软件工程智能体框架。在这种严格最小条件下，复现的默认努力配置达到70.7±3.5%的成功率（opus-5，三次运行的平均值），而fable-5在最大努力下达到78%。当将训练好的路点工具与原始动作一同作为可选能力暴露时，混合的fable-5智能体在默认努力下达到76.7±0.6%，其环境步数减半，墙上时间不到最大努力原始动作运行的四分之一。受控干预表明，能力主要围绕模型展开：模型选择显著改变成功率，框架影响是描述性的，而强制路点界面有助于较弱模型，但可能阻碍较强模型。然而，在较长视野任务上性能急剧下降，而延迟和上下文增长限制了持续运行。这些结果表明，智能体控制在零样本导航中已具有竞争力，并且模型、框架和界面为自主具身智能体提供了互补路径。

## Abstract
Autonomous embodied agents must sustain a long decision-making loop that involves perceiving, acting, verifying, and self-correcting over many steps. Current systems sustain this loop through task-specific workflows or embodied policies. We study a third form, agentic embodied control, in which a general-purpose agent holds the loop itself. Using zero-shot navigation as a controlled testbed, we evaluate three software-engineering agent harnesses given only a monocular RGB camera and discrete actions. Under this strictly minimal condition, replicated default-effort configurations reach 70.7$\pm$3.5% success (opus-5, mean over three runs), and fable-5 reaches 78% at maximum effort. When a trained waypoint tool is exposed alongside primitives as an optional capability, the hybrid fable-5 agent reaches 76.7$\pm$0.6% at default effort, using half the environment steps and less than one quarter of the wall time of the maximum-effort primitive run. Controlled interventions show that capability is primarily model-centered: model choice strongly changes success, harness effects are descriptive, and a forced waypoint interface helps weaker models but can hinder stronger ones. Performance nevertheless falls sharply on longer-horizon tasks, while latency and context growth limit sustained operation. These results show that agentic control is already competitive in zero-shot navigation and that models, harnesses, and interfaces offer complementary paths toward autonomous embodied agents.

## 1. 论文的核心问题与整体含义

- **背景与动机**：自主具身智能体需要在长时间内维持"感知—行动—验证—自我纠正"的决策循环。现有系统主要分为两类：一类是**策略驱动**（把导航能力内化在模型权重中，如 NaVid、Qwen-RobotNav），另一类是**工作流驱动**（用人类编写的固定流程和外部模块为冻结的 LLM/VLM 补充导航结构，如 NavGPT、MapGPT）。近年来的工业级"慢—快"双脑架构（ABot-N1、InternVLA-N1）虽引入层次化推理，但控制权仍掌握在人类编写的代码手中。
- **核心问题**：能否让**通用智能体（模型本身）掌控具身交互循环**？即模型自主决定何时观察、采取什么动作、如何纠错、何时停止，而非依赖外部环境循环或人类预设的流水线。
- **整体含义**：论文提出"**智能体具身控制**"（Agentic Embodied Control）这一第三种组织形式，并证明在极简接口下，通用软件工程智能体在零样本导航中已能达到与工业级训练策略相当的性能水平。这一发现重新定义了能力归属问题——导航能力大量来自模型本身，而非导航专用脚手架。

## 2. 论文提出的方法论

- **核心思想**：将导航问题从"训练策略"或"构建工作流"转化为"通用智能体自主控制"。具体做法是用原本为软件工程设计的通用智能体 harness（如 mini-swe-agent、Claude Agent SDK、Codex CLI），配合一个**最小感知—行动接口**，让前沿 VLM 自主完成导航决策。
- **极简接口（Minimal-Interface Probe）**：
  - `observe()`：返回一张 512×512 前视单目 RGB 图像（HFOV 90°），不推进环境。
  - `step(actions)`：执行由四个 Habitat 离散原语组成的动作序列——FORWARD（前进 0.25m）、LEFT/RIGHT（左/右转 15°）、STOP（终止回合）。
  - **无任何导航专用支持**：无深度、无全景图、无位姿、无地图、无里程计、无碰撞反馈、无航点候选项、无跨回合记忆、无搜索策略。
- **系统架构**：harness 负责维护会话、调用工具、返回结果，但**不预设交互顺序**；模型在每个回合接收完整交互历史，自主决定下一步动作。
- **三个可分离因素**：
  - **模型（Model）**：通用 VLM，决定导航能力上限；
  - **框架（Harness）**：通用智能体框架，维持交互；
  - **接口（Interface）**：感知和动作的表达方式。
- **混合接口变体**：将训练好的深度航点预测器作为**可选工具**与原语动作同时暴露，让智能体自主决定何时调用，而非强制使用某一种动作空间。

## 6. 论文的主要结论与发现

- **极简接口已达工业级水平**：fable-5 在最大努力下达到 78% SR，opus-5 默认努力三次运行平均 70.7±3.5% SR，远超 AgenticNav（55 SR），与 OmniNav（70 SR）、ABot-N1（71 SR）等训练策略相当。
- **能力主要来自模型**：仅更换模型（锁定 harness 和接口），SR 跨度达 5–72 个百分点，是研究中最宽的变化幅度。
- **框架影响有限且方向不一致**：两种 harness 的差异在 1.7–7.3 SR 之间，属于描述性而非因果性。
- **接口的效果取决于模型强弱**：强制航点接口对弱模型增益显著（+37–38 SR），对最强模型几乎无增益（+0.7–1.3 SR），在 VLNVerse 上甚至反向降低性能（-4~6 SR）。
- **可选脚手架优于强制脚手架**：混合接口让 fable-5 达到 76.7±0.6% SR，超越任一固定接口，步数减半、墙钟时间减少至 1/4，且该粗到细策略并非提示词预设，而是智能体自主涌现。
- **长时程仍是重大瓶颈**：R2R-CE→RxR-CE，SR 从 75 跌至 26（原语）/39（航点）；上下文无界增长（最终回合中位数 33k tokens，最大 169k）导致延迟剧增。
- **失败模式是"静默的"**：25 个失败回合中 22 个宣称成功，自信程度与最终距离无相关性；典型机制是"正确怀疑但不纠正"（至少 10 回合出现）。
- **实物部署中推理迁移但具身感知缺失**：条件推理、人物区分、多段路线保持均成功，但身体感知（转身时机）、动作标定（转向不足）、空间记忆（计数/目标保持）严重缺失。

## 7. 优点

- **极简诊断接口设计高明**：将接口压缩到最少元素（一张图、四个动作），最大化隔离了"模型自身能力"这一变量，使能力定位变得清晰。
- **三维度分解框架**（模型/框架/接口）提供了理解具身智能体系统的新视角，突破了以往将三者混为一谈的分析方式。
- **"可选"vs"强制"脚手架的对比极具洞察力**：证明了设计哲学的重要性——同样一个训练好的航点模块，作为强制控制路径会阻碍强模型，作为可选工具则同时提升成功率、速度和成本效率。
- **失败分析质量高**：25 个失败回合全部逐帧审计，分类互斥、覆盖完整，揭示出"自我诊断而不自我纠正"这一关键认知缺口。
- **实物部署补充了仿真盲区**：真实机器人体现了仿真中难以捕捉的"身体感缺失"问题，增强了结论的外部效度。
- **与工业界可比性强**：直接对标 ABot-N1、Qwen-RobotNav 等近期工业系统，表明学术原型能达到同等水平。

## 8. 不足与局限

- **长时程能力明显不足**：RxR-CE 上 SR 仅为 26–39%，与短时程的 70–78% 差距悬殊，证明该方法尚不具备持续自主运行能力。
- **上下文无界增长**：每次调用重新发送全部历史，token 消耗随回合推进爆炸式增长（最大 169k tokens），严重限制部署可行性。
- **实验覆盖存在偏差**：
  - 仅评估 rand100 子集（100 回合），并非完整 val-unseen；
  - 多数单元单次运行，缺少统计显著性检验；
  - 训练系统的结果来自不同分割，比较仅为参考性质；
  - 未测试开源模型的自部署方案在相同规模下的表现。
- **接口极简也意味着缺失关键信息**：无碰撞反馈和位姿信息导致几何类失败（如网格伪影、镜像误导）难以避免，部分失败属于接口设计造成的可避免错误。
- **跨模型比较存在服务差异**：不同模型的推理路径、服务版本、默认努力度不可完全对齐，影响了 harness 对比的因果解释力。
- **物理机器人实验为定性评估**：无 ground-truth 位姿和自动成功标签，31 个回合靠人工判读，结果属于探索性而非受控基准。
- **模型选择局限**：使用的模型均为闭源前沿模型（Claude、GPT 系列），未深入分析开源模型的可行性与差距。
- **提出"引导循环"假说但未验证**：关于脚手架生成数据→训练更好模型→简化脚手架的闭环仅停留在讨论层面。
